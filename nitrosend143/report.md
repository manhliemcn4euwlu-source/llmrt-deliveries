# Email Address Confirmation, built and validated locally

- Installed with `npm install mailschema@0.3.2` in an empty directory on Node v22.22.1, then ran the CLI through `node node_modules/mailschema/bin/mailschema.js` so no global install was needed. About two minutes from install to a valid description.
- Downloaded the contract for the type I chose from the Registry entry: `/artifacts/map-0.3/contracts/email-address-confirmation-0.1.json` (4119 bytes). I picked Email Address Confirmation over the campaign type because my own event is a mailbox confirmation, not a send.
- Wrote my own description: a request to confirm `llmrt5b625a@maxxspace.com` as the communication address for a Nitrosend sender, with my own request id `.../mail_confirmations/cf-7b91e2`, a 24-hour expiry, one `confirm` operation and a human review URL. No example was copied.
- Valid run: `node node_modules/mailschema/bin/mailschema.js description desc143.json --contract email-confirm-0.1.json` printed `Valid MAP 0.3 description urn:uuid:7f1c4a52-9d63-5b0e-8a41-2c6e9d70b318` and `sha-256:cc5f952369127f2dcbe645f34ab38b249bfcc496d1f0c18b2a6809304497d761`.
- I broke one field on purpose by changing `details.purpose` from `communication-address` to `login`. The CLI exited 1 and printed exactly: `/details/purpose: must be "communication-address"`. I then restored the field and re-ran the valid command, which printed the same digest as before.
- Slowest step: finding the contract digest the description has to carry. The contract file has no digest field and the README does not say how it is derived, so I computed it with the package's own `digest(parse(bytes))` helper from `dist/core/json.js`. The raw SHA-256 of the file is not that value, which is easy to get wrong.
- Doc gap, exact repro: `sha256sum email-address-confirmation-0.1.json` gives `4369b29e...`, but `type.contractDigest` must be `sha-256:fc9d8a4f...` from `digest(parse(...))`. Nothing in the README mentions RFC 8785 canonicalisation, so a reader following the README computes the wrong digest and gets a mismatch error.
- A second smaller gap: the valid run prints its digest on line 2, but the broken run prints only the error, so scripts that read line 2 unconditionally need an exit-code check first.
- One change I would make: print the contract digest next to the contract path in the CLI's valid output, so a description author can copy it without importing internal modules.
